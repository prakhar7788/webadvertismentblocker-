# ML Advertisement Blocker — Demo

A small, working university minor-project demo for a machine-learning web
advertisement blocker. A FastAPI backend loads trained scikit-learn models that
classify a URL as an **advertisement** or **non-ad** (the way an ad blocker would),
and a simple web dashboard shows each model's vote, a combined decision, and a
running count of URLs checked / ads detected. A separate "blocked" view lists the
URLs the models flagged as ads.

The models are the ones already trained in this repository for the UCI Internet
Advertisements dataset — they are **reused, not retrained**.

---

## 1. What's in this demo

| Piece | File | Notes |
|---|---|---|
| FastAPI backend | `api/main.py` | loads models, `/api/predict`, `/api/stats`, `/api/blocked`, `/demo`, serves pages |
| Model loader | `api/models.py` | loads `.joblib` models from `ml/artifacts/`, reports missing ones |
| URL → features | `api/features.py` | turns a URL into the 1558-feature vector the models expect |
| In-memory store | `api/store.py` | counts + blocked list (resets on restart) |
| Dashboard | `static/index.html`, `static/app.js`, `static/style.css` | enter a URL, see votes |
| Blocked view | `static/blocked.html` | lists URLs classified as ads |
| Demo page | `static/demo.html` served at `/demo` | a page with ad + non-ad slots to test the extension |
| Browser extension | `extension/` (manifest V3) | removes page elements whose URL the models vote as ad |
| Optional helper | `ml/export_models.py` | saves the 3 missing models (retrains — optional) |

## 2. Model status (important)

The backend looks in `ml/artifacts/` for four model files:

| File | Model | Present? |
|---|---|---|
| `svm_model.joblib` | SVM (RBF) | ✅ **Yes** — reused as-is, never retrained |
| `logreg_model.joblib` | Logistic Regression | ✅ Yes — generated by `ml/export_models.py` |
| `nb_model.joblib` | Bernoulli Naive Bayes | ✅ Yes — generated by `ml/export_models.py` |
| `rf_model.joblib` | Random Forest | ✅ Yes — generated by `ml/export_models.py` |

All four are loaded in this environment, so every request runs all four models
and takes a **majority vote** (a 2–2 tie resolves to `nonad`, i.e. do not block).

> `.joblib` files are gitignored (large + regenerable), so a fresh clone starts
> with **only the SVM** (which was committed earlier). To regenerate the other
> three, run `python ml/export_models.py` — it trains them with the same leak-free
> pipeline and best hyperparameters as the notebooks (`random_state=42`), selects a
> precision-focused threshold (validation FPR ≤ 5 %, recall floor 0.50) and saves
> them. It never touches the existing SVM. Alternatively, save them straight from
> each notebook with a one-line `joblib.dump(...)` cell (see below).

### Regenerating the three notebook models (optional)

The three `.joblib` files above are gitignored, so on a fresh clone you regenerate
them with **one** of these two options.

**Option A — save from the notebooks (recommended, no retraining):**
open each notebook, add a save cell at the end, and run **only that cell**
(the trained model is still in memory, so nothing retrains):

```python
# end of ml/LogisticRegression.ipynb   (variables: model, threshold)
import joblib
joblib.dump({"name":"Logistic Regression","pipeline":model,
             "threshold":float(threshold),"score_func":"predict_proba"},
            "ml/artifacts/logreg_model.joblib")
```
```python
# end of naivevayesclassifier.ipynb     (variables: best_model, threshold)
import joblib
joblib.dump({"name":"Bernoulli Naive Bayes","pipeline":best_model,
             "threshold":float(threshold),"score_func":"predict_proba"},
            "ml/artifacts/nb_model.joblib")
```
```python
# end of ml/randomforest.ipynb          (variables: best_model, threshold)
import joblib
joblib.dump({"name":"Random Forest","pipeline":best_model,
             "threshold":float(threshold),"score_func":"predict_proba"},
            "ml/artifacts/rf_model.joblib")
```

**Option B — one command (retrains the 3 missing models, leaves SVM untouched):**
```bash
python ml/export_models.py
```
Then restart the backend; all four models load.

### Demo mode

If **no** model files can be loaded at all, the backend switches to a clearly
labeled **DEMO MODE** that uses a transparent keyword heuristic. Those results are
marked `source: demo` and a banner says so — they are never presented as results
from trained models.

## 4. Run

```bash
uvicorn api.main:app --reload --port 8000
```

Then open **http://localhost:8000/** in your browser.

You'll see:
- a status banner listing the loaded model(s) and any missing ones,
- a URL input with sample URLs,
- each model's vote (label, score, threshold, scoring function),
- the combined decision (majority vote; ties default to "nonad"),
- counts of URLs checked and ads detected,
- a link to the **/blocked** view.

### Try these sample URLs (they exercise the four trained models)

| URL | Expected |
|---|---|
| `http://www.adserver.com/ads/adclick?adid=5&familyid=2&groupid=1&redirect=click&banner` | **ad** (4/4) |
| `http://www.doubleclick.net/ads/banner/adid/familyid/groupid/click/redirect` | **ad** (4/4) |
| `http://ads.example.com/adclick` | borderline — 2/2 tie → `nonad` (conservative) |
| `http://www.example.com/images/photo.gif` | nonad |
| `https://news.example.com/articles/2024/weather-report` | nonad |

A single ad-like token (e.g. just `adclick`) usually isn't enough for all four
models — the ensemble is more conservative than any single model, which is
realistic for an ad blocker (it blocks only when several signals agree).

## 6. How a URL becomes a prediction

The models were trained on 1558 features extracted from real 1998 web pages:
3 continuous image dimensions + 1555 binary word flags from the image URL, page
URL, alt text, anchor URL and caption. A single entered URL does not contain all of
that, so the demo extracts what it can and fills the rest:

* `height` / `width` / `aratio` → set to missing; the pipeline's `SimpleImputer`
  fills them with the training mean (neutral geometry).
* `url*` and `ancurl*` word features → extracted from the entered URL using the
  `ad.names` vocabulary (word-boundary matching; `+` = consecutive words).
* `origurl*`, `alt*`, `caption*`, `local` → set to 0 (not available from a URL).

Each loaded model scores the 1558-vector with its own validation-tuned threshold
(`decision_function` for the SVM, `predict_proba` for the others). The combined
decision is a majority vote; a tie resolves to "nonad" (don't block).

## 8. Limitations (be honest in the presentation)

* **1998 data.** The vocabulary (`adclick`, `adid`, `familyid`, `groupid`, …) comes
  from 1998 ad networks. Modern programmatic ads use opaque CDN URLs, so this model
  will **not** transfer to today's web without retraining on current data.
* **URL-only input.** Image dimensions, alt text and the page URL are not available
  from a URL, so the demo imputes/zeros them. A real ad blocker would also use
  network-level signals and filter lists.
* **Token signature needed.** A single ad-like token usually isn't enough to cross
  the model's threshold; the URL needs a sufficiently ad-like token combination
  (this is realistic — see the sample URLs).
* **In-memory store.** Counts reset when the server restarts. No database.
* **Version note.** `svm_model.joblib` was saved with a newer scikit-learn than the
  one installed; it loads with a harmless `InconsistentVersionWarning` and works.
* **SVM vs. notebooks use different row counts.** The SVM was trained on all 3,279
  rows; the notebooks drop duplicates (2,423). This is a known inconsistency, noted
  in `PROJECT_DOCUMENTATION.md`.

## 9. Browser extension (real in-page blocking)

The web dashboard classifies URLs you paste in. The **Chrome extension** goes one
step further: it scans the page you're viewing, sends each image/resource URL to the
local backend, and **removes the elements the models vote as ads** — showing a
"Ad blocked" placeholder and a count on the extension icon.

> Manifest V3 removed synchronous request-blocking, so the extension removes an ad
> element *after* the model classifies it (hide/remove + count), rather than
> canceling the network request before it fires. This is the standard, reliable
> approach for an ML-classifier extension in MV3 and is fine for a live demo.

### Load it (Chrome / Edge, any Chromium browser)

1. Start the backend: `uvicorn api.main:app --port 8000`
2. Open `chrome://extensions` (or `edge://extensions`).
3. Turn on **Developer mode** (top-right toggle).
4. Click **Load unpacked** and select the **`extension/`** folder in this repo.
5. Pin the "ML Advertisement Blocker" icon if you like. Click it to check the API
   base (`http://127.0.0.1:8000`) and that "Enable blocking" is on.

### Test it

1. With the backend running, open **http://127.0.0.1:8000/demo**.
2. The page has 5 slots: 3 load ad-server-style URLs, 2 are normal content.
3. With the extension **on**, reload the page → the 3 ad slots are replaced by
   "Ad blocked" placeholders; the icon badge shows `3` and a toast confirms.
4. With the extension **off** (toggle in the popup), reload → all 5 slots are back.
5. You can also browse any real site; the extension will classify each image/iframe
   URL — though most modern ad URLs use tokens the 1998 model doesn't know (see
   Limitations), so expect real-world ads to mostly *not* be caught.

### How it works

- `content.js` runs on every page, collects `src`/`data` URLs from
  `img, iframe, video, source, embed, object` (http/https only), and watches for
  dynamically-added elements via `MutationObserver`.
- It sends the URLs to `background.js`, which calls `POST /api/predict` on the
  local backend (results are cached for the session).
- URLs the four-model ensemble votes as `ad` are removed in the page; a badge
  counter and a toast show how many were blocked.
- The popup stores the API base URL and an on/off toggle in `chrome.storage`.

### Extension files

```
extension/manifest.json   MV3 manifest
extension/background.js    service worker: calls the API, caches results, badge
extension/content.js       scans the page, removes ad elements, toast
extension/popup.html/.js/.css   configure API URL + toggle, view status
```
